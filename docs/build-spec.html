The build prompt

nila-build-prompt.txt 
# NILA — on-device infant safety monitor (Android, Kotlin)

ROLE
You are building a two-phone Android app for a 30-hour hackathon judged on
working product quality, on-device AI use, and technical depth. Optimise for a
system that demonstrably works offline over one that has more features.

PRODUCT
Two Android phones on the same local network:
  GUARDIAN  an old phone placed at the crib. Camera + mic. Runs all inference.
  PARENT    the user's phone. Live view, alerts, logs, guidance, learning.
Hard constraint: no cloud, no account, no analytics, no network calls beyond
the LAN. The product must work end-to-end with the router unplugged
(Wi-Fi Direct fallback). This is a headline feature, not an optimisation.

STACK — pin these, do not substitute
  Kotlin 2.x, Jetpack Compose (Material 3), minSdk 26, targetSdk 35
  CameraX                    preview + ImageAnalysis
  AudioRecord                16 kHz mono PCM16, 960 ms window, 50% overlap
  LiteRT (TF Lite)           + Qualcomm AI Engine Direct (QNN) accelerator
                             GPU delegate fallback, CPU last resort
  MediaPipe Pose Landmarker  (Tasks Vision), LITE model, 5-8 fps
  MediaPipe LLM Inference    Gemma 3n E2B int4, on the PARENT phone only
  Room                       local persistence, no remote sync
  Foreground services        camera + microphone types, on GUARDIAN

MODULE LAYOUT
  :app            navigation, theme, screens
  :core-audio     capture, ring buffer, log-mel frontend
  :core-vision    CameraX analyzer, pose, geometric safety rules
  :core-ml        model load, delegate selection, latency benchmarking
  :core-events    fusion, severity tiers, Room entities, debounce
  :core-transport pairing, LAN video, event sync
  :core-llm       Gemma session, prompt assembly, streaming output

AUDIO PIPELINE (Guardian)
1. AudioRecord 16 kHz mono into a lock-free ring buffer.
2. Every 480 ms emit the last 960 ms as log-mel (64 mels, 25 ms win, 10 ms hop).
3. Cry classifier: YAMNet (TFLite) day one — AudioSet already has
   "Baby cry, infant cry". Read that logit plus "Speech" and "Silence".
   Upgrade later to a fine-tuned MobileNetV3 head on log-mel if time allows.
4. Smooth with a 3-of-5 majority vote before declaring CRY_START.
5. Track the episode: start time, duration, RMS envelope sampled at 1 Hz,
   peak intensity, and whether the envelope is rising or settling
   (linear fit over the last 20 s).
   NEVER classify WHY the baby is crying. Reason is not a label in this app.

VISION PIPELINE (Guardian)
CameraX ImageAnalysis at 5-8 fps -> Pose Landmarker -> geometric rules over
landmarks, evaluated against a user-drawn crib quadrilateral:
  ROLLOVER       shoulder-hip vector flips from supine to prone, held 5 frames
  FACE_COVERED   nose+eyes landmark confidence < 0.3 while torso is tracked,
                 held 2 s (distinguishes occlusion from "left the frame")
  EDGE_APPROACH  any landmark within 12% of the crib polygon edge
  CLIMB_OUT      hip landmark rises above the crib rail line, held 3 frames
Every rule needs hysteresis: N frames to fire, M frames to clear, N != M.
Log every rule evaluation with its input values — you will need this to debug
at 3am and to prove technical depth to judges.

EVENT FUSION + SEVERITY
  L0 QUIET      nothing
  L1 NOTE       movement, brief fuss (< 20 s). Logged only.
  L2 ATTENTION  cry episode confirmed > 20 s, or FACE_COVERED < 2 s.
                Push to parent phone.
  L3 URGENT     ROLLOVER to prone, or FACE_COVERED > 2 s.
                Parent full-screen alert + Guardian local tone.
  L4 CRITICAL   CLIMB_OUT or EDGE_APPROACH with rising trajectory.
                Guardian sounds IMMEDIATELY at full volume, on-device,
                WITHOUT waiting for network acknowledgement from the parent.
L3/L4 must never depend on the transport layer. This is the whole safety claim.

ON-DEVICE LLM (Parent phone)
Gemma 3n receives structured evidence, never raw audio, and never a label:
  { cry: { duration_s, intensity, trend, confidence },
    context: { hours_since_feed, last_sleep_end, last_diaper, room_temp_c,
               baby_age_months },
    recent_events: [ ... last 6 ... ] }
System prompt must enforce: state the most likely explanation WITH its
reasoning, name the competing explanation, give 2-3 concrete actions, and
say plainly when the acoustic evidence alone is not conclusive. Never output
a bare diagnosis. Never mention SIDS. Always allow "I'm not sure — here's
what to check first." Answer in the language the user selected.

TRANSPORT
Pairing by QR code shown on Guardian, scanned by Parent (6-digit fallback).
Video over WebRTC on the LAN; events over a small local socket with a JSON
schema, at most a few messages per second. Encrypt with a key derived from
the pairing secret. If discovery fails, fall back to Wi-Fi Direct.

SELF-TEST (build this early, it is your demo opener)
One button on the Parent phone plays a recorded cry through its speaker.
The Guardian must detect it and surface the event within 2 s. Show the
measured end-to-end latency on screen. This proves the system works in five
seconds flat and doubles as onboarding.

BUILD ORDER — do not reorder
  1. Pairing + camera preview streaming Guardian -> Parent
  2. AudioRecord loop + YAMNet on CPU, event fires, Parent shows it
  3. Swap to LiteRT QNN accelerator; log and display per-model latency
  4. Pose Landmarker + ROLLOVER rule only, tested with a doll
  5. FACE_COVERED + crib polygon drawing UI
  6. Room persistence + event timeline + quick-log buttons
  7. Gemma 3n reasoning screen
  8. Micro-lesson cards triggered by event type
  9. Office Kit laptop dashboard mirror
 10. Airplane-mode rehearsal

NON-GOALS — refuse these if asked
  No cry-reason classification as a label.  No RTSP/CCTV integration.
  No cloud sync, accounts, or telemetry.    No iOS.
  No medical claims of any kind.            No breathing/vitals monitoring.

Design system — "Nightlight"

The design decision that carries the whole app: this is a 2am product. A parent opens it half-asleep, one-handed, in a dark room, next to a sleeping infant. Every choice below follows from that, and every one of them is defensible out loud to a jury — which is worth more than a prettier palette with no reasoning behind it.

Why dark-only

Ship one theme, deliberately

A white screen at 2am is hostile and wakes the room. Committing to dark-only halves your theming work and is a stronger design statement than a mediocre pair of themes. Say it on stage: "we didn't build a light theme, because nobody uses this at noon."

Why amber

Warm accents, not blue

Amber and warm tones carry the least short-wavelength light, so the UI disturbs adapted night vision and infant sleep less than the blue every other app defaults to. It is a nightlight, rendered as an interface — and it's a real reason, not a mood board.

The discipline that keeps it from looking generic

  • ruleOne dominant hue. Amber is roughly 70% of your coloured pixels. Sage appears only on all-clear states. Attention and urgent appear only at their severity level and nowhere else — the moment you use urgent red as a decorative accent, it stops meaning anything at 3am.
  • ruleSeverity is encoded in form, not just colour. L2 is a chip. L3 is a full card. L4 takes the entire screen. A colour-blind parent, or one looking from across a room, still reads the difference.
  • avoidNo pastel baby-blue or nursery-pink. It reads as a toy, and this is a safety instrument. No accent stripes down card edges, no gradient heroes — both are instantly recognisable as filler.

Motion and touch

Motion

Slow by default, fast only for danger

The armed indicator breathes on a 3.2s cycle. Screen transitions 220ms ease-out. The only fast motion in the app is an L3/L4 alert arriving — so speed itself becomes a signal. Honour Settings.Global.ANIMATOR_DURATION_SCALE.

Touch

One hand, in the dark

Every primary control in the bottom third. Minimum 56dp targets, 64dp for alert actions. Quick-log buttons (fed / slept / changed) big enough to hit without looking. No swipe-only actions anywhere — a half-asleep parent will not discover them.

The honesty components

This is the part of the UI that no competitor has, and the reason your research finding becomes a product advantage rather than an awkward footnote. Three components carry it.

Component 1

The intensity curve

A sparkline of RMS over the episode, with the trend named in words: rising, settling, steady. This is real, measurable information about the cry — unlike a reason label — and it's what a parent actually wants to know from the next room.

Component 2

Evidence chips

Every explanation shows the inputs it used as tappable chips: rising, 3h10 fed, 31°C. The reasoning is inspectable. Tap one and it explains its contribution.

Component 3

The hedge line

A fixed slot in the Reading card that states what the system cannot tell. "The sound alone can't separate hunger from discomfort." It is always present, never empty, never boilerplate.

The rule

No bare labels, ever

The string "Your baby is hungry" must not exist in the codebase. Grep for it before you demo. Every explanation carries its reason and its uncertainty, or it doesn't ship.

Severity model

Get this right and the safety story is credible. Get it wrong and the app either cries wolf all night or misses the thing it exists to catch.

L0
Quiet. Nothing rendered, nothing stored. Most of the night lives here.
L1
Note. Movement, a brief fuss under 20s. Written to the timeline, no notification. Builds the night's story without waking anyone.
L2
Attention. Confirmed cry over 20s, or a face briefly covered. Notification on the Parent phone, amber chip, no sound by default.
L3
Urgent. Rollover to prone, or face covered beyond 2s. Full-screen alert, sound, haptic. Guardian sounds locally too — it does not wait for the parent phone to acknowledge.
L4
Critical. Climb-out or edge approach with rising trajectory. Guardian alarms immediately at full volume, on-device, before any network round trip. The alert must beat the fall, not report it.

The two failure modes that lose you the demo

  • flappingWithout hysteresis, every rule oscillates and the demo becomes a fire alarm. Require N consecutive frames to fire and a different M to clear. Tune with a doll and a towel before you tune anything else.
  • silent failureIf the Guardian's camera or mic dies, the Parent phone must say so within 10 seconds. A monitor that fails quietly is worse than no monitor, and a judge will ask what happens when it breaks. Have the answer on screen.

Where to spend your hours

Their rubric is published, so treat it as a spec. Ranked by return per hour, not by weight alone — some criteria are cheap to max out and some are not.

End product quality30%
Spend the most here, and spend it on finishing rather than adding. Their rubric says outright that a well-built simple product beats a broken complex one. Two P0 features that never fail beat five that mostly work. The single highest-value hour of your build is the airplane-mode rehearsal at H25.
Novelty and impact20%
You already have this, and it costs you almost no build time — it's a slide. Three claims: safety AI that until now needed a ₹18,000–₹35,000 camera, running on a phone from a drawer; a system that states its uncertainty in a category full of overclaiming; and the leakage finding from your own research, which is the credibility anchor for everything else you say.
HackTracker — creative phone use15%
Free points, if you build the product as specified. Read from device data, not self-reported: camera, mic and NPU inference running continuously on two phones in different roles is about as strong as this metric gets. Make sure both devices are logged in and active for the whole window.
Technical depth15%
One slide wins this: the latency table. Per-model, CPU vs GPU vs NPU, measured on the actual device via Qualcomm AI Hub and your own instrumentation. Add the quantisation choice, the hysteresis constants, and why L4 fires locally. Concrete numbers beat architecture diagrams every time.
HackTracker — Office Kit10%
Cheap to earn, easy to forget. Mirror the Guardian's live event timeline to the laptop and use it as your actual debugging surface from hour 3 onward. Genuine sustained use, not a five-minute cameo at the end — it's measured from device data.
Demo and presentation10%
Weighted lowest, decides the most. Two scored rounds feed the Top 10 and the final pitch picks winners, so presentation gates everything. Rehearse three times, timed, out loud. Script below.

The five-minute demo

Open with the product working, not with slides. Bring a doll and a small towel — you need something to roll over and something to put over its face.

0:00 – 0:30
Cold open, no slides. Two phones on the table, one at a doll. "This costs nothing. It does what a ₹30,000 monitor does." Hit self-test: a cry plays, the Guardian catches it, latency appears on screen. You've proven it works before you've introduced yourself.
0:30 – 1:15
The stake. One slide, three numbers from your own research: 5.6% of parents of 6-month-olds admitted smothering, slapping or shaking their baby over crying; 27% report crying problems in the first four months; ~20% of infants cry excessively, linked to parental anxiety and depression. Then: "the existing answer costs ₹30,000 and ships your baby's video to a cloud."
1:15 – 2:30
Safety, live. Roll the doll prone — L3 fires. Towel over the face — L3. Lift it towards the rail — L4, and the crib phone alarms on its own. Then say the line that lands: "that alarm didn't touch the network. It has to beat the fall, not report it."
2:30 – 3:15
The honesty beat. Show the Reading card. "Published cry classifiers report 96–99% accuracy. We built one — 98.76%. Then we split by infant instead of by clip and it fell to chance, which matches the 2026 controlled study on this corpus. So we don't tell you why your baby is crying. We show you the evidence and say what we can't know." This is the moment the jury remembers.
3:15 – 4:00
Under the hood. Airplane mode on, both phones — everything still works. The latency table: NPU vs GPU vs CPU on this device. Gemma 3n answering in Hindi or Tamil, offline, on the phone in your hand.
4:00 – 4:40
The market gap. Thirty seconds: real safety AI is locked in $199–$399 hardware; the free two-phone apps have no intelligence at all. India is the fastest-growing market in Asia Pacific at 8.9% CAGR. Nobody occupies the middle.
4:40 – 5:00
Close on the constraint, not the roadmap. "No cloud, no subscription, no new hardware. It's an awareness aid, not a medical device — and we're careful about that line." Then stop talking.

Demo insurance

  • Record a full working video at H25 and have it queued. Demo live anyway — but never be the team whose only copy was live.
  • Bring a battery pack for both phones and a small Bluetooth speaker in case the room is loud.
  • Pre-set the crib polygon for the demo table and save it — don't re-draw it on stage.
  • Rehearse the doll choreography. Fumbling the rollover for fifteen seconds costs more than any missing feature.

The hour-13 rule

  • If Pose Landmarker isn't stable by H13, ship rollover only and move every remaining vision hour to the Reading screen and the demo. A polished two-feature product outscores a broken four-feature one, and their rubric says so in as many words.
  • If the QNN accelerator isn't up by H7, fall back to the GPU delegate and keep building. Revisit it at H21 if you're ahead — never at H12.
